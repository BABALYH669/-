## 一、GPIO 与八种工作模式

### 1. GPIO 的 8 种工作模式可分成哪两大类？

| 大类                 | 包含模式                    | 特点               |
| ------------------ | ----------------------- | ---------------- |
| **输入模式**（只看不发）     | 浮空输入、上拉输入、下拉输入、模拟输入     | MOS 管全关，引脚只用来读电平 |
| **输出模式**（只发不看/外设发） | 推挽输出、开漏输出、推挽复用输出、开漏复用输出 | 芯片主动输出高低电平，或交给外设 |
上拉输入:空闲时默认为高电平
下拉输入:空闲时默认为低电平

典型场景：
- **按键 → 上拉输入**：按键一端接引脚、一端接 GND，松开时引脚被内部上拉拉高为 1，按下接地变 0，检测下降沿/低电平。
- **点灯 → 推挽输出**：LED 是输出型负载，由单片机主动给高/低电平点亮熄灭。
- **串口 TX → 复用推挽**：TX 引脚由 USART 外设控制输出，不归 GPIO 寄存器管。
- **I2C 总线 → 复用开漏**：SDA/SCL 需要"线与 + 上拉拉高"，必须开漏结构。

> ❗对照你的作答：你把"点灯"说成"下拉输入"，方向反了——LED 是**输出**（推挽输出），不是输入；按键接 GND 按下为低，应配**上拉输入**（不是下拉）。上拉/下拉的选择取决于空闲时想让引脚停在什么电平。

### 2. 三种输入模式的内部电路本质区别与空闲电平

| 模式 | 内部结构 | 外部无信号时电平 |
| --- | --- | --- |
| 浮空输入 | 上拉、下拉电阻**全关** | 由外部电路决定；悬空则**飘忽不定** |
| 上拉输入 | 打开弱上拉电阻（30~50KΩ） | 默认**高电平**（外部接 GND 才拉低） |
| 下拉输入 | 打开弱下拉电阻 | 默认**低电平**（外部接 VCC 才拉高） |

### 3. 浮空输入为什么"飘忽不定"？适合接什么信号？

因为引脚内部无上下拉、呈**高阻**状态，电平完全由外部决定；没有外部明确驱动时，引脚电平受漏电流/电磁干扰影响在高低间乱跳。

适合接：**外部电路本身已给出明确电平**的信号，如串口 RX（对端驱动）、传感器数字输出；或外部自己接了上拉/下拉电阻的按键。

### 4. 模拟输入与其它输入模式的根本区别

- 其它输入模式都要经过**施密特触发器**整形（输出 0/1 数字电平）；
- **模拟输入**：关闭施密特触发器、关闭上下拉电阻，引脚直接连到片内 **ADC 采样电路**，只传**模拟电压（0~3.3V）**，不转数字。
- 模拟输入引脚本质就是专门给 ADC（模数转换器）设计的

要用 ADC 采电压，对应引脚**必须配置成模拟输入（`GPIO_MODE_ANALOG`）**，否则采样不准或读不到。

### 5. 开漏输出为什么出不了高电平？如何"线与"？

- 内部**只用 NMOS，PMOS 永远断开**：
  - 输出低 → NMOS 导通，引脚被拉到 GND；
  - 输出高 → NMOS 断开，引脚**悬空（高阻）**，自己无法驱动到高电平。
- 所以必须**外接上拉电阻**才能输出高电平（也可借此实现 3.3V→5V 电平转换）。
- 多个开漏输出可直接并联：谁输出低谁把总线拉低，输出"高"的一方是高阻不参与，逻辑上即"**线与**"（有 0 则 0）。

### 6. 推挽输出的内部工作过程

- 输出高：**PMOS 导通**、NMOS 关断 → 引脚接到 **VDD（3.3V）**；
- 输出低：**NMOS 导通**、PMOS 关断 → 引脚接到 **GND**。

两条管子轮流导通、主动驱动，因此**驱动能力强、速度快**。

### 7. 通用推挽 vs 复用推挽：控制权在谁手里？

| 模式 | 控制权 | 典型用途 |
| --- | --- | --- |
| 通用推挽 `GPIO_MODE_OUTPUT_PP` | **CPU/GPIO 寄存器**直接控制 | LED、蜂鸣器、普通高低电平 |
| 复用推挽 `GPIO_MODE_AF_PP` | **片内外设**（USART/SPI/定时器等）控制 | 串口 TX、SPI 时钟/数据、PWM 输出 |

串口 TX、PWM 属于外设输出信号，所以用**复用推挽**：引脚的控制权交给对应外设，而不是用 GPIO 去手动翻转。

### 8. GPIO 初始化流程（HAL 库）

四个结构体成员：`Pin`（引脚号）、`Mode`（工作模式）、`Pull`（上下拉）、`Speed`（翻转速度）。

完整流程：

```c
GPIO_InitTypeDef gpio_init_struct;   // 1. 定义初始化结构体
元件_GPIO_CLK_ENABLE();              // 2. 使能该端口时钟（最重要，第一步）
gpio_init_struct.Pin   = GPIO_PIN_5;        // 引脚编号
gpio_init_struct.Mode  = GPIO_MODE_OUTPUT_PP; // 工作模式
gpio_init_struct.Pull  = GPIO_PULLUP;        // 上下拉
gpio_init_struct.Speed = GPIO_SPEED_FREQ_HIGH; // 翻转速度
HAL_GPIO_Init(GPIOB, &gpio_init_struct);    // 3. 调用 HAL 初始化
```

**为什么时钟使能是第一步**：STM32 外设默认时钟是关闭的（省电），寄存器无时钟就无法读写；漏掉时钟使能，对引脚/寄存器的配置**完全不生效**（无输出、读不到正确电平），是 GPIO 最常见的坑。

## 二、外部中断 EXTI 与 NVIC

### 1. 引脚号与 EXTI 线的对应、AFIO 的作用

- **固定对应**：引脚号 = EXTI 线号，即 `Px0→EXTI0`、`Px1→EXTI1`……`Px15→EXTI15`。
- 因为 PA0、PB0、PC0 的**引脚号都是 0**，所以都挂在同一条 **EXTI0** 线上——**同一时刻只能有一个端口使用这条线**。
- 系统区分端口靠 **AFIO 外设的 EXTICR1~EXTICR4** 寄存器：每根 EXTI 线配 4 位，写入 `0000=PA、0001=PB、0010=PC……`，即"给 EXTI0 选 PA0 还是 PB0"。例：PC13 → EXTI13 → EXTICR4 对应 4 位写 `0010`。
	- EXTICR1:EXTI0~4   0001:EXTI1,  0010:EXTI1,   0100:EXTI2,   1000:EXTI4
	- EXTICR2:EXTI5~8
	- EXTICR3:EXTI9~12
	- EXTICR4:EXTI12~15
- 使用前需先使能 **AFIO 时钟**；HAL 库一般会自动完成配置。

### 2. 中断号分组

| 中断号（IRQn）        | 覆盖 EXTI 线     | 对应引脚      | 中断服务函数名                |
| ---------------- | ------------- | --------- | ---------------------- |
| `EXTI0_IRQn`     | EXTI0         | 所有 Px0    | `EXTI0_IRQHandler`     |
| `EXTI1_IRQn`     | EXTI1         | 所有 Px1    | `EXTI1_IRQHandler`     |
| `EXTI2_IRQn`     | EXTI2         | 所有 Px2    | `EXTI2_IRQHandler`     |
| `EXTI3_IRQn`     | EXTI3         | 所有 Px3    | `EXTI3_IRQHandler`     |
| `EXTI9_5_IRQn`   | EXTI5~EXTI9   | Px5~Px9   | `EXTI9_5_IRQHandler`   |
| `EXTI15_10_IRQn` | EXTI10~EXTI15 | Px10~Px15 | `EXTI15_10_IRQHandler` |

EXTI0~4 每根线**独占一个中断向量**；5~9、10~15 因引脚数量限制**共用一个中断向量**（中断服务函数只有 9 个），所以名字按区间命名。Px5 与 Px15 的服务函数分别是 `EXTI9_5_IRQHandler` 和 `EXTI15_10_IRQHandler`——这也是为什么要在函数里用 `GPIO_Pin` 判断具体是哪根线触发。

### 3. 上拉配下降沿 / 下拉配上升沿的原理

- **上拉输入**：空闲=高电平。按键按下接 GND → 高变低 → 产生**下降沿**，故配下降沿触发。
- **下拉输入**：空闲=低电平。按键按下接 VCC → 低变高 → 产生**上升沿**，故配上升沿触发。

即：上下拉决定了**空闲电平**，按键按下产生的是"从空闲电平反方向跳变"的边沿，两者要配对（例程 KEY_UP 用下拉 + 上升沿，KEY0/KEY1 用上拉 + 下降沿）。

### 4. 抢占优先级 vs 响应优先级

| 概念 | 含义 | 能否打断 |
| --- | --- | --- |
| 抢占优先级 | 决定中断能否**打断**正在执行的其它中断 | 数字**越小越高**，高抢占可打断低抢占 |
| 响应（子）优先级 | 抢占相同时，决定谁**先被响应** | 不打断，只排队比先后 |

- 数字越小优先级越高（0 最高）。
- 分组 `[2:2]`：用 2 位做抢占（0~3，4 级）、2 位做响应（0~3，4 级）。
- 中断分组**整个工程只能设置一次**，一般在 `HAL_Init()`/`HAL_NVIC_SetPriorityGrouping` 中完成；重复设置会导致优先级判定混乱（例程默认分组 2）。

### 5. 调用链各环节职责

```
按键按下 → ①ISR → ②HAL_GPIO_EXTI_IRQHandler → ③Callback → 返回主程序
```

| 环节 | 职责 |
| --- | --- |
| ① ISR（`EXTIx_IRQHandler`） | 名字必须与中断向量表一致，调用公共处理函数并**清标志**，不做业务 |
| ② `HAL_GPIO_EXTI_IRQHandler` | HAL 公共处理：确认中断来源、**清除中断标志**、分发到回调 |
| ③ `HAL_GPIO_EXTI_Callback` | **用户业务逻辑**（翻转 LED、置标志等） |

业务逻辑写在 Callback 而非 ISR：HAL 把"清标志+分发"的固定流程封装在弱定义回调框架里，用户只需重写回调；ISR 保持最小化、可复用、不易出错。

### 6. 为什么退出前再强制清一次标志

`HAL_GPIO_EXTI_IRQHandler` 内部已经清过一次标志，但在**退出回调函数前**再调 `__HAL_GPIO_EXTI_CLEAR_IT` 强制清空一次，是为了**彻底杜绝按键抖动/重复触发**造成的标志残留——防止同一中断事件在退出后又被再次误判触发。不清可能造成**重复进入中断、逻辑执行多次**。

### 7. 为什么要双重判断（Pin + ReadPin）

- `if(GPIO_Pin == GPIO_PIN_x)`：因为 5~9、10~15 是多根线共用一个中断服务函数，需要区分到底是哪根线进来；
- 紧接着 `HAL_GPIO_ReadPin(...) == 0/1` 再确认**当前电平**：中断标志在边沿瞬间置位，若此刻实际电平仍处于"按下/松开"状态，说明是真实触发而非抖动残留（例如下降沿触发后，读到仍为低=确实按下）。这是**软件消抖 + 防误触发**的双保险。

### 8. `__weak` 弱定义的好处

- HAL 给回调提供了一个**默认空实现**（弱定义）：用户不重写，程序也能正常编译链接（相当于"钩子"预留）；
- 用户**重写同名函数**即可覆盖默认实现、挂上自己的业务，无需改 HAL 源码。
- 注意：**函数签名必须与弱定义完全一致**（返回类型、参数列表，如 `void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)`），否则重写无效（新函数会被当作另一个函数）。

## 三、USART 串口

### 1. 通信方式概念与 UART 归属

| 分类 | 含义 |
| --- | --- |
| 串行通信 | 数据**逐位按顺序**传输：线路简单、抗干扰强、适合远距离 |
| 并行通信 | 数据**多位同时**传输：速度快，但抗干扰差、成本高、距离短 |
| 单工 | 只能沿一个方向传输 |
| 半双工 | 可双向，但**分时**进行 |
| 全双工 | 可**同时**双向传输 |
| 同步 | 收发**共用同一时钟信号** |
| 异步 | 无时钟线，靠数据帧中的**起始位/停止位**对齐 |

**UART = 串行 + 全双工 + 异步 + 点对点**（TX/RX 两根线）。

### 2. 比特率与波特率

- 比特率：每秒传送的**比特数**（bit/s）；
- 波特率：每秒传送的**码元数**（Baud）；
- 关系：`比特率 = 波特率 × log₂M`（M 为每个码元承载的比特数/电平数）。
- 二进制系统 M=2，`log₂2=1`，所以**波特率数值上等于比特率**。

### 3. USARTDIV 计算与 BRR 写入

过采样 16 倍 → 计数时钟 = 72MHz / 16 = 4.5MHz；但 USART 波特率公式：`波特率 = 时钟频率 / (16 × USARTDIV)`，即：

```
USARTDIV = 72000000 / (16 × 115200) = 72000000 / 1843200 = 39.0625
```

- 整数部分 `mantissa = 39`；
- 小数部分 `fraction = 0.0625 × 16 + 0.5 ≈ 1`（`×16` 是把小数换算成 4 位二进制能表示的值，`+0.5` 是**四舍五入**取整）；
- 写入 `USART1->BRR = (mantissa << 4) + fraction`。

**为什么左移 4 位**：`BRR` 寄存器中 **mantissa 占 bit[15:4]（高 12 位），fraction 占 bit[3:0]（低 4 位）**，所以整数部分要左移 4 位拼进去。小数 `×16` 等价于左移 4 位，是 mantissa 存高位的逆运算。

### 4. 为什么中断接收要"开一次、回调里再开一次"

`HAL_UART_Receive_IT(&huart, buf, 1)` 的含义是"**启动一次**接收并开中断"——它使能 RXNE 中断、等待收 1 个字节。收到 1 字节后**本次接收就结束了，中断随之关闭**。

所以：

- `usart_init` 里调一次：让系统"挂起"第一次接收；
- 回调 `HAL_UART_RxCpltCallback` 里**必须再调一次**：为接收下一字节重新挂起接收。

不重启的后果：**只收第一个字节，之后串口再也不进中断**，后续数据全部丢失。而 `HAL_UART_IRQHandler` 会清除中断标志，故重启动作要放在回调里完成。

### 5. TX/RX 引脚模式与 MspInit

- **TX（PA9）→ 复用推挽输出**：发送数据由 USART 外设驱动输出，所以是"复用"，要能主动推高低电平所以是"推挽"；
- **RX（PA10）→ 输入模式**：接收时引脚是被外部信号驱动的，MCU 只负责读，所以配输入（可加内部上拉保证空闲为高）。

`HAL_UART_MspInit`（MSP = MCU Support Package）在 `HAL_UART_Init()` 内部被**自动调用**，负责"外设之下"的底层配置：**外设与 GPIO 时钟使能、引脚模式初始化、NVIC 中断优先级与使能**。用户不需要手动调用它。

### 6. BRR 寄存器位分配

BRR 是 16 位寄存器，实际**全部 16 位都用**，只是分工不同：

- `bit[15:4]`（12 位）：整数部分 mantissa（USARTDIV 的整数）；
- `bit[3:0]`（4 位）：小数部分 fraction（USARTDIV 的小数 ×16）。

小数位只有 4 位（精度 1/16），这正是波特率会存在理论误差、需要四舍五入的原因。

### 7. 字长 / 停止位 / 校验位

| 参数 | 作用 |
| --- | --- |
| WordLength 8B | 1 字节数据，**无奇偶校验位** |
| WordLength 9B | 数据 9 位，**含 1 位奇偶校验位**（第 9 位） |
| StopBits | 帧结束标志（1/0.5/1.5/2 位停止位），用于同步下一帧 |
| Parity | 奇偶校验：偶校验 EVEN / 奇校验 ODD / 无 NONE，用于**简单检错**（统计 1 的个数奇偶） |

需要校验时选 9 位字长，收发双方校验方式必须一致。

### 8. printf 重定向与半主机模式

- MDK 中 `printf` 最终通过 `fputc` 输出字符；默认 `fputc` 走 **半主机模式（semihosting）**——即把 I/O 交给**调试器/主机**处理（依赖调试环境、有仿真器时才能工作）。
- 裸机调试、脱机运行时没有主机，半主机调用会卡死/进硬件异常，所以要：
  1. 声明**不使用半主机**（`__use_no_semihosting` / `#pragma import(__use_no_semihosting)`）；
  2. **重写 `fputc`**，把字符写入 `USART1->DR`（先轮询 `USART1->SR` 的 TXE 位等待上一字符发完）。

这样 `printf` 就从"打印到调试器"变成"打印到串口"。

## 四、定时器（基本 / 通用 / 高级）

### 1. 三种定时器横向对比

| 特性     | 基本定时器 TIM6/7 | 通用定时器 TIM2~5          | 高级定时器 TIM1/8                     |
| ------ | ------------ | --------------------- | -------------------------------- |
| 主要功能   | 仅定时          | 定时、输入捕获、输出比较、PWM、外部计数 | 定时、捕获、PWM + **互补输出、死区、刹车**       |
| 通道     | 无输入输出通道      | 4 个独立通道               | 4 通道 + **3 个互补通道(CHxN)**         |
| 独有功能   | 可触发 DAC      | 编码器/霍尔接口、多定时器同步       | **重复计数器 RCR、可编程死区、刹车 BKIN、互补输出** |
| 总线     | APB1         | APB1（倍频后 72MHz）       | APB2                             |
| DMA/中断 | 仅更新事件        | 捕获/比较/更新均可            | 捕获/比较/更新均可                       |
| 典型应用   | 简单时基、系统心跳    | 编码器测速、PWM 调速、输入捕获测频   | 电机控制（六步 PWM）、逆变器、数字电源            |

> 记忆：基本=定时器，通用=信号捕获/生成，高级=电机/电源专用（互补、死区、刹车、重复计数都归高级）。

### 2. 定时周期公式与计算

向上计数：**`Tout = (ARR + 1) × (PSC + 1) / Tclk`**

- 例：72MHz、`PSC=71`、`ARR=499`：
  - 计数频率 = 72MHz / (71+1) = **1MHz**；
  - 溢出周期 = (499+1) / 1MHz = **500 µs**（中断频率 2kHz）。
- 要 1ms 中断：`PSC=71`（→1MHz）、`ARR=999` → (999+1)/1MHz = 1ms。也可 `PSC=7199`、`ARR=9` 等任意组合，只要 (PSC+1)(ARR+1)/72MHz = 1ms。

### 3. 影子寄存器、ARPE 与 UG

- **影子寄存器**：真正参与硬件工作的寄存器，**不可直接访问**，在更新事件（UEV）时从预装载寄存器装载。
- `ARPE=0`（无缓冲）：写 ARR **立即**写入影子寄存器，随时生效；
- `ARPE=1`（有缓冲）：写 ARR 先存预装载寄存器，**等下一个更新事件**才装入影子寄存器生效。
- 带缓冲的好处：在计数过程中修改 ARR 不会让当前周期"突变"，更新值统一在溢出点生效，**减小误差、波形稳定**。
- `EGR` 的 **UG 位**：软件产生一次更新事件，强制把预装载值立刻装入影子寄存器（改参数后想马上生效就置 UG）。

### 4. 为什么 APB1 定时器是 72MHz

AHB=72MHz → APB1 预分频器 ÷2 → PCLK1=36MHz。**APB1 定时器时钟的规则**：

- APB1 分频系数 = 1 时：定时器时钟 = PCLK1；
- APB1 分频系数 > 1 时：定时器时钟 = **2 × PCLK1** = 72MHz。

STM32F103 的 APB1 是 2 分频（36MHz），所以 TIM2~7 的计数时钟被自动 ×2 为 **72MHz**。这条规则是为了补偿 APB1 低速，让定时器仍能拿到高频时钟。

### 5. 溢出条件与更新事件

- 向上计数：CNT 从 0 递增，当 **CNT == ARR（影子）** 时溢出 → 计数器回 0 → 产生**更新事件**。
- 更新事件**默认产生**（硬件行为），但**中断和 DMA 请求默认不产生**。
- 要更新中断：调用 `HAL_TIM_Base_Start_IT(&htim)`（使能 UIE + 启动计数器）。事件与中断的关系可记作：**EGR 产生事件，DIER 决定是否"叫醒 CPU"，SR 记录事件是否发生**。

### 6. PWM 中各参数作用

| 参数 | 决定什么 |
| --- | --- |
| `PSC` | 计数频率（决定 PWM 频率的分辨率基础） |
| `ARR` | **PWM 周期**（溢出周期 = 载波周期） |
| `CCRx`（比较值） | **占空比**：CNT 计到 CCRx 时输出翻转 |

- PWM1 模式：`CNT < CCRx` 输出**有效电平**（由 OCPolarity 定高/低有效）；`CNT ≥ CCRx` 输出无效电平。
- 例：`ARR=500`、`CCR=250` → 50% 占空比。
- 运行时动态调占空比：`__HAL_TIM_SET_COMPARE(&htim, TIM_CHANNEL_x, 新值)`（例程呼吸灯 0~300 循环改 CCR2）。

### 7. 输入捕获测脉宽的原理

基本思路：**记录高电平起点和终点对应的计数值，两者之差 × 计数周期 = 脉宽**。

流程（测高电平宽度）：

1. 初始配置**上升沿捕获**；
2. 捕获到上升沿 → 清计数器（起点为 0）→ **切换为下降沿捕获**；
3. 捕获到下降沿 → 读 CCR（终点值）→ 该值即高电平宽度（单位=计数周期）；
4. 主循环组合结果打印。

**为什么清计数器再切沿**：保证起点从 0 开始、终点读到的是"从上升沿到下降沿"的净计数，避免两次捕获之间的无关计数。

**超过一个计数周期（65536）怎么办**：ARR=0xFFFF 时计数溢出会回 0，此时开**更新中断**累计溢出次数：

```
总时间 = (溢出次数 × 65536) + 捕获值   （单位：计数周期）
```

例程状态变量 `g_timxchy_cap_sta` 低 6 位就是溢出计数：高电平太长/溢出达上限时直接判定 0xFFFF。

### 8. 输入捕获例程参数的意义

- `ARR = 0xFFFF`：让计数范围最大化（65536 个计数），减少溢出频率，配合溢出次数还原长时间；
- `PSC = 72-1`：计数频率 = 72MHz/72 = **1MHz** → 每个计数 = **1 µs**，读到的值直接就是微秒数，便于换算。

最长测量：溢出计数字段 6 位（最多 63 次溢出）→ 最长 ≈ `63×65536 + 65535 ≈ 4.19 s`（按 1µs 计数）。单轮不溢出的极限约 65.5ms。

### 9. 切换捕获极性为什么要"先清再设"

`TIM_RESET_CAPTUREPOLARITY` 先把该通道的极性位（CCER 的 CCxP/CCxNP）**全部复位成默认**，再 `TIM_SET_CAPTUREPOLARITY` 写入新极性。

直接设置时，若上一次配置的其它极性位仍残留，会形成**冲突/错误组合**（尤其高低有效位是成对编码的），导致边沿检测错乱。**先复位再设置**是保证干净切换的固定套路（例程两处都写了"一定要先清除原来的设置"）。

### 10. 互补输出 + 死区 + 重复计数器

- **为什么需要互补输出**：电机 H 桥/逆变器的上下桥臂需要一对**反相**驱动信号（CH1 与 CH1N）。
- **为什么需要死区**：开关器件有导通/关断延迟，若上下管同时导通会**直通短路**烧毁电路；在两路切换之间插入一段"都不导通"的**死区时间**即可避免。死区时间用 `TIM_BreakDeadTimeConfigTypeDef.DeadTime` 编程配置。
- **重复计数器 RCR 输出 N 个脉冲**：RCR 让"每溢出 N+1 次才产生一次更新事件"。套路：在更新中断里维护剩余脉冲数 `remain`，每产生一次更新事件 `remain--` 并把 `RCR = remain-1` 继续；`remain==0` 时**关闭定时器/停止输出**——从而实现"精确输出 N 个 PWM 后自动停"（例程 `atim_timx_npwm_chy_set(N)`）。

### 11. PWM 输入模式（一通道测周期+脉宽）

利用**从模式 Reset + 双通道映射同一条输入线 TI1**：

- CH1：捕获**上升沿**（`TIM_ICSELECTION_DIRECTTI` 直连 TI1）；
- CH2：捕获**下降沿**（`TIM_ICSELECTION_INDIRECTTI` 间接映射到 TI1）；
- 从模式配置为 **Reset**：每次 TI1 上升沿到来时**自动清零计数器**。

于是每个周期起点被硬件自动清零：

- CH2 捕获值 = **高电平脉宽**；
- CH1 捕获值 = **周期**（下一次上升沿时的计数值）。

**为什么 CH2 只捕获不开中断**：CH2 的值由硬件在下降沿自动写入 CCR2，无需 CPU 参与；若在 CH2 中断里读值，可能与 CH1 读取的时刻不一致，导致**周期和脉宽不属于同一个完整周期**（数据不匹配）。只让 CH1 中断（周期结束点）一次读两个值，保证两值属于同一已完成周期。

## 五、ADC

### 1. ADC 类型与 12 位分辨率

| 类型 | 优点 | 缺点 |
| --- | --- | --- |
| 并联比较型 | 转换速度最快 | 成本高、功耗高、分辨率低 |
| 逐次逼近型（SAR） | 结构简单、功耗低 | 转换速度慢 |

- STM32F103 的 ADC 是**逐次逼近型**（12 位、最快 1µs 左右）。
- 12 位分辨率：把参考电压 0~3.3V 分成 **2¹² = 4096 个刻度**，数字量范围 0~4095，即 ADC 能分辨的最小模拟量 = 3.3V/4096 ≈ 0.8mV。

### 2. ADC 时钟与分频配置

- STM32F103 的 ADC 最大工作频率 **14MHz**，超过会降低精度甚至转换异常。
- PCLK2=72MHz → 取 **6 分频** = 12MHz（稳定常用）。
- 配置方式：`HAL_RCCEx_PeriphCLKConfig(&adc_clk_init)`，其中 `adc_clk_init.AdcClockSelection = RCC_ADCPCLK2_DIV6`；底层实际写的是 **RCC->CFGR 的 ADCPRE[1:0] 位**（2/4/6/8 分频）。

### 3. 采样时间与转换时间

- 采样时间越长：采样电容充电越充分 → **精度/稳定性越高**，但**转换速度越慢**；
- 本例选 **239.5 个周期**（最长）：测普通电压不需要高速，选最长时间换取稳定（信号源内阻大时更必须长采样时间）；
- 完整转换时间 ≈ **采样时间 + 12.5 个固定周期**（12 位逐次逼近的固定开销）。239.5 + 12.5 = 252 周期，在 12MHz 下约 **21 µs**。

### 4. 电压换算、为什么除 4096、校准

- 公式：**`电压 = 读数值 × (参考电压 / 4096)`**，如 `adc_val × (3.3/4096)`。
- 除 4096 的理由：满量程对应 4096 个刻度（2¹²），理想映射是 `digital = Vin/Vref × 4096`；读到的 4095 实际对应 `4095/4096 × 3.3 ≈ 3.299V`，工程上直接按 4096 换算（也规避了"满码=参考电压"的近似差异），12 位单通道例程与 16 位过采样例程（/65536）都按这个理想刻度换算。
- **为什么要校准**：ADC 内部电容阵列存在失调/增益误差，校准可消除零点偏移、提高精度。
- **时机**：每次上电后、开始转换之前调用 `HAL_ADCEx_Calibration_Start(&hadc)` 一次。

### 5. 规则组 / 注入组 / 扫描模式

| 组 | 可安排转换数 | 特点 |
| --- | --- | --- |
| 规则组 | 最多 **16 个** | 常规转换，结果存入 ADC_DR |
| 注入组 | 最多 **4 个** | 有"特权"：**可以打断规则组**的转换，保证重要信号及时采集，结果存 JDRx |

- 多通道按顺序采集要用**扫描模式**（`ScanConvMode = ENABLE` → CR1 的 SCAN 位），ADC 按规则序列 SQR 依次转换所有选中通道。
- 关闭扫描模式时即使配了多通道，也只转换**第一个**通道。

### 6. 单次 vs 连续转换

- 单次：每次转换完成后停止，**每次要重新 `HAL_ADC_Start` 才转下一次**（例程每轮 Start→Poll→GetValue）；
- 连续：一次 `HAL_ADC_Start` 后**自动持续转换**，每转完一轮立刻开始下一轮。

连续模式配 `ENABLE` 后，主循环里直接 `HAL_ADC_GetValue` 读最新值即可，**不用反复 Start**（但要配合适当延时/中断控制读取节奏）。单次模式忘记重新 Start 是"读到的值永远不更新"的常见原因。

### 7. DMA 参数：为什么外设不增、内存递增、半字

- **外设地址不递增**：ADC 数据寄存器 `ADC1->DR` **只有一个固定地址**，每次结果都从同一地址读；
- **内存地址递增**：接收缓冲 `g_adc_dma_buf[]` 是数组，需要依次存放每个采样点；
- **半字（16 位）**：ADC 分辨率 12 位、数据寄存器 16 位——字节(8位)装不下、字(32位)浪费且可能错位，半字正好匹配 DR 的有效宽度。

### 8. Normal 模式为什么需要手动重装（adc_dma_enable）

DMA Normal 模式**传完 CNDTR 指定数量后自动停止**；此时 ADC 即使还在连续转换，也不再产生 DMA 请求（DMA 已关）。要做"下一批"采集，必须手动重来：

```
关 ADC(ADON=0) → 关 DMA(EN=0) → 等待硬件确认关闭 → 重设 CNDTR → 开 DMA → 开 ADC → 置 SWSTART 触发转换
```

**为什么改 CNDTR 前必须关 DMA**：STM32 手册要求——`CNDTR` 只能在 DMA 通道**关闭（EN=0）**时加载；通道运行中写 CNDTR **无效/可能出错**。所以例程先清 CCR 的 EN 位、`while` 等它真正关掉，再写 CNDTR。

> 之所以不用 `HAL_ADC_Start_DMA` 直接重启，是因为 HAL 状态机在部分场景会冲突，寄存器级操作更可靠。

### 9. DMA 中断为什么只"置标志 + 清标志"

中断服务函数追求**短小快速**，避免长时间占用中断上下文（会阻塞其它中断/破坏实时性）。数据处理（求和、均值滤波、显示）耗时，放在**主循环**里做最合适。

主循环收到 `g_adc_dma_sta == 1` 后的固定动作：**处理数据 → 清标志（置 0）→ 调用 `adc_dma_enable()` 启动下一轮采集**。不清标志会反复处理同一批旧数据；不重启则只采一轮。

### 10. 过采样提高分辨率

- 原理：噪声平均。**采样次数每提高 4 倍，等效分辨率提高 1 bit**（4¹=4→+1bit，4²=16→+2bit…即 4ⁿ）。
- 12 位 → 16 位要提高 **4 bit**：需要 4⁴ = **256 次**采样取平均。
- 平均后数值范围也放大了 256 倍，要**右移 4 位**（`>>N`，N=提高的位数）还原成 16 位有效值：`4096×256=1048576`，右移 4 位 → 65536 = 2¹⁶。
- **代价**：采样速度降低 256 倍（256 次采样才出 1 个结果）；且受 ADC 自身性能限制，分辨率不能无限提高，要按实际需求权衡。

## 六、DMA

### 1. DMA 全称与核心思想

- DMA = **Direct Memory Access，直接存储器访问**。
- 核心思想：把数据从一个地址空间搬到另一个地址空间（典型 **外设 DR ↔ 内存**），**传输过程由硬件完成、不占用 CPU**。
- 解决的问题：大量/高速数据传输时为 **CPU 减负**，让 CPU 腾出时间跑业务（如 ADC 连续采 100 个点，CPU 只在搬完后的中断里处理一次）。

### 2. DMA_InitTypeDef 各字段含义（ADC 场景填法）

| 字段 | 含义 | ADC 场景填法/原因 |
| --- | --- | --- |
| `Direction` | 传输方向 | `DMA_PERIPH_TO_MEMORY`（外设→内存） |
| `PeriphInc` | 外设地址是否递增 | `DISABLE`：ADC->DR 只有一个地址 |
| `MemInc` | 内存地址是否递增 | `ENABLE`：数组依次存放每个采样点 |
| `PeriphDataAlignment` | 外设数据宽度 | 半字：ADC 12 位结果在 16 位 DR 中 |
| `MemDataAlignment` | 内存数据宽度 | 半字：与源宽度一致 |
| `Mode` | 操作模式 | `DMA_NORMAL`：传完指定数量停止（便于分批） |
| `Priority` | 通道优先级 | 视需求（例程 HIGH） |

底层映射：这些字段写入 `DMA_CCRx` 的 DIR/PINC/MINC/PSIZE/MSIZE/CIRC/PL 位。

### 3. Normal vs Circular

| 模式 | 行为 | 适合场景 |
| --- | --- | --- |
| Normal（普通） | 传完 CNDTR 指定数量后**停止** | 一批采集一批处理，处理时数据不被新数据覆盖（本实验用） |
| Circular（循环） | 传完自动从头**循环覆盖**写缓冲区 | 持续不间断采集，配"半满/全满中断"或双缓冲取数据 |

**为什么多通道 ADC 用 Normal**：例程要在 DMA 搬完 300 个数后统一处理、显示，Normal 保证"搬运-处理"时序清晰，处理过程中缓冲区不会被新数据覆盖；若用 Circular 需额外处理覆盖问题。

### 4. 传输完成标志与清除

- 标志位置：**`DMA1->ISR`** 状态寄存器，通道 1 传输完成标志为 **bit1（TCIF1）**（通道 x 对应 bit 4x+1）。
- 清除方式：向 **`DMA1->IFCR`**（中断标志清除寄存器）的对应位**写 1**（`DMA1->IFCR |= 1<<1`）。
- 例程中断服务函数即：`if(DMA1->ISR & (1<<1)) { g_adc_dma_sta=1; DMA1->IFCR |= 1<<1; }`。

### 5. 开传输完成中断的意义 / 不用中断怎么知道搬完

- 意义：DMA 搬完一批后**主动打断 CPU**（进中断置标志），CPU 无需轮询等待，效率高、实时性好。
- 不用中断的替代：CPU **轮询 `DMA1->ISR` 的 TCIF 标志**或查询 `DMA1_Channelx->CNDTR` 是否减到 0。但轮询占用 CPU，违背 DMA"减负"的初衷，一般只在简单场景用。

## 七、独立看门狗 IWDG / 窗口看门狗 WWDG

### 1. IWDG 的本质、复位条件、喂狗

- 本质：**能产生系统复位信号的递减计数器**；检测电磁干扰/硬件异常导致的"程序跑飞"，是异常处理的**最后手段**（不可依赖，平时要尽量避免异常）。
- 时钟：**独立的 RC 振荡器（LSI，约 40kHz）**，独立于系统时钟，可在待机/停止模式下运行，即使主时钟停振也能工作。
- 复位条件：递减计数器**计数到 0x000** 时产生系统复位。
- 喂狗（寄存器层面）：在计数到 0 之前向键寄存器 **IWDG_KR 写入 0xAAAA**，把重装载寄存器 RLR 的值重新装入计数器。

### 2. IWDG_KR 键值含义

| 写入值 | 动作 |
| --- | --- |
| `0x5555` | **解除 IWDG_PR 和 IWDG_RLR 的写保护**，允许访问预分频/重装载寄存器 |
| `0xAAAA` | **喂狗**：把 RLR 值重装载进计数器，防止归零复位 |
| `0xCCCC` | **启动看门狗**（开始递减） |

**为什么要先写 0x5555**：PR、RLR 受写保护，防止程序意外篡改看门狗参数（比如误把超时改得很短导致不断复位）；只有先解锁才能写。另注意：RLR 只有在 `IWDG_SR` 的 RVU 位为 0（上次更新完成）时才能修改。

### 3. IWDG 超时时间计算（40kHz、÷32、RLR=1250）

```
预分频后计数频率 = 40kHz / 32 = 1.25kHz
计数周期        = 1 / 1.25kHz = 0.8ms
超时时间        = (重装载值 + 1) × 计数周期 = (1250 + 1) × 0.8ms ≈ 1.0008s ≈ 1s
```

> 通用公式：`Tout = (4 × 2^prer) × (rlr + 1) / fLSI`（prer 为 PR 寄存器分频因子）。喂狗间隔必须**严格小于**超时时间并留 30% 以上余量（例程先试 1010ms > 1s → 不断复位；改 900ms → 正常）。

### 4. IWDG 为什么关不掉？调试怎么处理

- IWDG 一旦使能**只能用系统复位关闭**，软件无法停止——这是它"独立 + 最高安全级别"的设计（防止程序异常时自己把看门狗关掉）。
- 调试时问题：IWDG 在**调试器暂停**时仍继续计数 → 程序停在断点就不断复位，导致无法单步/下载。
- 处理：调试阶段用调试单元冻结看门狗（如 `HAL_DBGMCU_EnableDBGStopMode()` 等 DBGMCU 冻结功能），或先把喂狗代码跑通、再临时关掉 IWDG 进行调试，最后再开启验证。

### 5. WWDG 复位条件与"窗口"概念

| 对比点 | IWDG | WWDG |
| --- | --- | --- |
| 复位条件 | 减到 **0** 复位 | 减到 **0x3F**（T6 位由 1 跳变到 0）复位 |

**"窗口"的含义**：WWDG 不仅不能喂得太晚，也**不能喂得太早**：

- 计数器初值 0x7F 递减，窗口上限由 `W[6:0]` 指定（例程 0x5F=95）；
- 计数器值**大于窗口值**时喂狗 → 复位（太早，说明程序执行异常地快/乱序，可能没走完该走的流程就在喂狗）；
- 计数器减到 **0x3F 以下**（T6 变 0）→ 自动复位（太晚）。

**允许喂狗的条件：`0x3F < 计数器当前值 ≤ 窗口值 W`**（例程有效窗口 95~64，共 32 个计数 ≈ 29ms）。WWDG 专门用来检测**程序运行时效是否精准**（软件异常：任务执行太快或太慢）。

### 6. EWI 提前唤醒中断

- 触发点：计数器递减到 **0x40** 时（比复位点 0x3F 早一个计数）产生中断，条件是 `WWDG_CFR` 的 EWI 位=1 且对应 NVIC 中断使能。
- 意义：**最后一次喂狗/补救机会**——到 0x40 还不喂，再减一个到 0x3F 就复位了。可用于记录现场、保存关键数据或在此喂狗。
- 中断里喂狗注意：动作要**快**（不要做耗时操作）、及时清标志；确保中断**不被更高优先级长时间阻塞**，否则仍会复位。例程完全靠 EWI 喂狗：主循环延时 90ms（已超最大超时 58ms）也不复位。

### 7. IWDG 与 WWDG 六维对比

| 维度 | IWDG | WWDG |
| --- | --- | --- |
| 时钟源 | **LSI**（40kHz，独立于系统时钟） | **PCLK1**（APB1，36MHz，依赖系统时钟） |
| 计数器位数 | **12 位**（RLR 最大 0xFFF=4095） | **7 位**（T[6:0]，最大 0x7F=127） |
| 喂狗窗口限制 | **无**，归零前喂即可 | **有窗口**，须在 `0x3F < CNT ≤ W` 内喂，太早太晚都复位 |
| 提前中断 | **无** | **有 EWI**（0x40 触发） |
| 能否软件关闭 | 一旦使能**只能复位关闭** | 复位后自动关闭（调试可 DBG 暂停） |
| 超时量级 | 几 ms ~ 几 s（范围广） | 几十 ms 以内（较快） |

一句话：**IWDG 防"系统死掉/时钟停振"，WWDG 防"程序时序错误（太快或太慢）"**。

### 8. 复位标志检测的作用

- `__HAL_RCC_GET_FLAG(RCC_FLAG_WWDGRST)` 判断**上一次复位是否由窗口看门狗引起**（非 0 = WWDG 复位；0 = 外部/其它复位）。
- 为什么要判断：产品出现反复复位时，先搞清楚**复位来源**，才能对症下药（是看门狗超时、程序跑飞，还是外部按键复位）。
- 为什么读后要清：`RCC_FLAG_*` 复位标志是**锁存**的，不清会一直保持；下次上电再判断会**误判**（把历史复位当成本次复位）。所以读完后调用 `__HAL_RCC_CLEAR_RESET_FLAGS()` 清零。IWDG 对应 `RCC_FLAG_IWDGRST`，同理。

## 八、I2C 总线与 OLED（SSD1306）

### 1. I2C 通信组合、上拉电阻、"释放 SDA"

- I2C = **同步 + 串行 + 半双工**、可多主机，两根线：SDA（数据）、SCL（时钟）。
- **为什么需要上拉电阻**：I2C 设备输出级是**开漏结构**，自己只能拉低、不能主动输出高电平；高电平靠外接（或内部）**上拉电阻**把总线拉高。SDA 无上拉 → 总线无法回到高电平，通信失败（OLED 黑屏的常见原因之一）。
- **"释放 SDA"**：主机发完数据后不再拉低 SDA，让上拉电阻把总线拉回高电平，把 SDA 的控制权交给从机（或其它主机）。
- 主机不释放的后果：SDA 一直被拉低，**从机无法拉低总线返回 ACK**（从机要应答必须自己拉低，而总线已被主机占住），通信立刻乱套。

### 2. 起始 / 停止信号与数据位时序

| 信号 | SCL 与 SDA 的跳变 |
| --- | --- |
| 起始 START | **SCL 为高电平时，SDA 由高 → 低** |
| 停止 STOP | **SCL 为高电平时，SDA 由低 → 高** |

- 规则：**只有当 SCL 为高电平时才操作（改变）SDA**——用来产生起始/停止信号；
- 传输数据位时，**SDA 只能在 SCL 为低电平时改变**；SCL 为高电平期间 SDA 必须**保持稳定**（此时 SDA 电平才被从机采样为 0 或 1）。

如果 SCL 高电平时 SDA 乱变，会被从机误判成起始/停止信号 → 通信错乱。

### 3. ACK / NACK 机制

- 每发完一个字节（8 位），主机**释放 SDA**，在第 **9 个时钟**上接收从机应答：
  - **ACK = SDA 被从机拉低**（低电平，表示"收到，继续"）；
  - **NACK = SDA 保持高**（从机不应答/忙/地址不对）。
- 从机返回 ACK 的前提：主机已释放 SDA（见第 1 题），从机主动把 SDA 拉低一个时钟。

### 4. I2C 完整写时序（含地址字节）

```
① 主机产生起始信号 START
② 发送从机地址字节 = (7位地址 << 1) | R/W 位   （写=0，读=1）
③ 等待从机 ACK
④ 发送寄存器地址 / 控制字节
⑤ 等待 ACK
⑥ 发送数据字节（可多个）
⑦ 等待 ACK
⑧ 主机产生停止信号 STOP
```

**OLED 地址问题**：SSD1306 的 7 位从机地址是 `0x3C`，发送时**左移 1 位**再拼读写位，即写操作发送字节 `0x3C<<1 | 0 = 0x78`（笔记/例程常把这个 8 位形式直接记为"从机地址 0x78"）。两个数指的是同一器件：`0x3C` 是 7 位地址，`0x78` 是它在总线上的完整首字节（含写位）。

### 5. SSD1306 如何区分"命令"与"数据"

靠**控制字节**（I2C 模式下写在数据段的最前面）：

| 控制字节 | 含义 | 去向 |
| --- | --- | --- |
| `0x00` | 后面是**命令** | 送入命令解码器，查表执行（如 `0xAE`=关显示） |
| `0x40` | 后面是**显示数据** | 直接写入 **GDDRAM**（1=亮点，0=灭） |

即：**同样的数值，前置控制字节不同 → 被分到不同功能通道**（命令通道 or 像素通道）。

**GDDRAM 坐标映射**（128×64）：

- 纵向分 **8 页**（Page0~7），每页 = 8 行，8×8 = 64 行；
- 每页 128 列，每列 1 字节，**字节的 bit0 对应本列第 0 行、bit7 对应第 7 行**；
- 写数据前先设页地址（`0xB0+page`）与列地址（高 4 位 + 低 4 位），随后发 `0x40` 可连续写入像素。

### 6. OLED 黑屏排查顺序

1. **GPIO 是否初始化**：必须调用 `iic_init()`，SCL/SDA 时钟与引脚配好；
2. **SDA 是否有上拉**：开漏输出必须使能内部上拉或外接 4.7kΩ，否则无高电平；
3. **电荷泵是否使能**：漏发 `0x8D, 0x14` → 黑屏（最易遗漏）；
4. **扫描方向是否匹配**：`0xA1`/`0xC8` 与模组不匹配会导致图像上下/左右颠倒（不是黑屏但显示错乱）。

**电荷泵为什么关键**：OLED 面板需要 **7~9V** 驱动电压，SSD1306 内部电荷泵负责把 3.3V **升压**到面板工作电压；`0x8D, 0x14` 是"开启电荷泵"命令，漏了它屏幕**完全没有驱动电压**，自然全黑。

## 九、SPI 与 NOR Flash（W25Q128）

### 1. SPI vs I2C

| 维度 | SPI | I2C |
| --- | --- | --- |
| 线数 | **4 根**：SCLK、MOSI、MISO、CS | **2 根**：SCL、SDA |
| 工作方式 | **全双工** | **半双工** |
| 同步方式 | 同步（主机提供 SCLK） | 同步（主机提供 SCL） |
| 协议特征 | **边沿协议**（按时钟边沿采样） | **电平协议**（SCL 高电平期间 SDA 稳定有效） |
| 其它 | CS 低电平有效片选，支持多从机 | 开漏 + 上拉，可多主机 |

### 2. SPI 四种模式与 W25Q128

四种模式由 **CPOL（时钟极性：空闲电平）** 与 **CPHA（时钟相位：第几个边沿采样）** 组合：

| 模式 | CPOL | CPHA | 特征 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 空闲低电平，**第一个边沿（上升沿）采样** |
| 1 | 0 | 1 | 空闲低电平，第二个边沿（下降沿）采样 |
| 2 | 1 | 0 | 空闲高电平，第一个边沿（下降沿）采样 |
| 3 | 1 | 1 | 空闲高电平，第二个边沿（上升沿）采样 |

- **W25Q128 支持模式 0 和模式 3**（数据手册要求）。
- 收发双方 CPOL/CPHA 必须一致，否则采到错误数据。

### 3. NOR Flash 为什么"只能写 0，不能写 1"

物理层面：Flash 存储单元是浮栅晶体管，**编程（写）操作只能把单元从 1 → 0**（逐位、逐字节进行）；要把 0 恢复成 1，必须对整块施加**高压电场擦除**，擦除会把整块所有位**全部置 1**（无法精确擦单个 bit）。

所以修改一个已存在的数据字节，标准三步：

1. **读**出目标**整个扇区/块**的数据到 RAM 数组；
2. 在 RAM 中**改写**需要修改的字节（要写 1 的位置靠擦除后本来就是 1）；
3. **擦除**该扇区（整块变 1）→ 把 RAM 中"保留数据 + 修改数据"**重新写回**扇区。

### 4. W25Q128 存储层级与 24 位地址

- 容量 128Mb = **16MB** = 16,777,216 字节 = 2²⁴。
- 层级：**256 块** → 每块 **16 扇区** → 每扇区 **16 页** → 每页 **256 字节**。
- 因为要精确寻址 2²⁴ 个字节（0x000000~0xFFFFFF），地址必须是 **24 位**；SPI 按字节传输，所以 24 位地址要**分高 8 位、中 8 位、低 8 位三次**发出（先发高位，MSB first）。

### 5. 读指令 0x03 与页编程指令 0x02

- **读数据 `0x03`**：`0x03 指令` + `24 位地址` → 从机在该地址起连续输出数据（可连续读，地址自动递增，跨页读不受 256 字节限制，直到片选拉高为止）。
- **页编程 `0x02`**：`0x02 指令` + `24 位地址` + 待写数据（**最多 256 字节 = 一页**）。
- **跨页注意**：页编程**不能跨页自动衔接**——地址到达页尾（256 字节边界）后会**回绕到本页开头**，把数据写到错误位置。因此要写超过 256 字节的数据，必须**按页分段**，每段单独发一次页编程指令。
- 补充：写指令前要先发**写使能**（`0x06`）并查询状态寄存器忙标志，Flash 写/擦除期间不接受新指令。

## 十、DAC 与 RTC

### 1. DAC vs ADC、为什么关输出缓冲

- **方向相反**：ADC 把模拟信号（传感器电压）→ 数字量给 MCU；**DAC 把 MCU 的数字量 → 模拟电压**输出给模拟控制系统。
- **关闭输出缓冲的原因**：DAC 输出缓冲（运放跟随器）存在**输出范围下限**（有最小输出电压/无法真正到 0V）。实验中要测接近 0V 的小电压，**关闭输出缓冲**才能让 DAC 直接输出到接近 0V 的满摆幅；使能缓冲时最低电压测不到 0V。
- 补充：DAC 相关的误差概念——比例系统误差（斜率偏差）、失调误差（斜率相同起点不同）、非线性误差（直线弯曲）。

### 2. DAC 的三种触发方式

| 触发方式 | 机制 |
| --- | --- |
| 自动（TEN=0） | 经过一个 DAC 周期**自动**把 DHRx 数据装入 DORx 输出 |
| 软件触发 | 触发源中 **SWTRIGx** 软件触发事件，把 DHRx → DORx |
| 外部事件 | **定时器 / EXTI_9** 等硬件产生事件，把 DHRx → DORx |

用定时器触发 DAC 的目的：**精确控制每次输出更新的时间间隔**（定时器周期 = 输出点间隔），配合 DMA 即可"定时定量"地连续输出波形，而不占用 CPU 逐点搬运。

### 3. 正弦波输出设计思路（查表法 + DMA + 定时器）

1. 预计算一个周期的正弦采样值表（如 256 个点，`sin(2π·i/N)·幅度` 存入数组）——查表法把"算正弦"变成"取数"，速度快；
2. 配置 **DAC 由定时器触发**，定时器更新频率 = 正弦波采样率（决定输出频率）；
3. 用 **DMA 循环模式**把正弦表自动搬运到 DAC 数据寄存器（DHRx），每个触发事件搬一个点；
4. 硬件按定时器节奏逐个输出 → 经输出缓冲/滤波得到平滑正弦波。

要点：改**表长或定时器频率**可调输出频率；改表中幅度可调幅值；CPU 只在初始化时参与，输出过程全由 DMA+定时器+DAC 硬件完成。

### 4. RTC 的本质与内/外置 RTC 对比

- 本质：**实时时钟（Real Time Clock）就是一个计数器**，计数频率常为秒，专门用于记录时间；带独立电源/后备域，**MCU 掉电后仍可运行**（VBAT 供电），且低功耗。
- 常用 **32.768kHz（LSE）晶振**的原因：32.768kHz = 2¹⁵，**正好 15 次二分频得到精确的 1Hz**（每秒计一次），用廉价低功耗晶振即可实现高精度秒计时。

| 对比因素 | 内部 RTC | 外置 RTC |
| --- | --- | --- |
| 信息差异 | 提供秒/亚秒信号 | 提供秒信号和日历 |
| 功耗 | 功耗较高 | 功耗低 |
| 体积 | 不占额外体积 | 体积大 |
| 成本 | 成本低 | 成本高 |

> 通用认知：外置 RTC 一般需设计外围电路、可配独立电源、时间寄存器多采用 **BCD 码**存储。
