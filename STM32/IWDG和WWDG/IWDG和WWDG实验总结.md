## 📘 STM32F103ZET6 看门狗实验笔记（IWDG & WWDG）

---

## 第一部分：独立看门狗 IWDG 实验

### 一、实验目的

1. 掌握 STM32 **独立看门狗 IWDG** 的初始化与喂狗方法。
2. 理解预分频器（Prescaler）和重装载值（Reload）如何决定超时时间。
3. 通过故意超时不喂狗，观察系统复位现象。

### 二、实验硬件

- STM32F103ZET6 开发板
- 使用串口打印信息，观察复位与喂狗状态
- 板上 LED 可辅助观察
### 三、实验步骤

4. **初始化 IWDG**
```c
iwdg_init(IWDG_PRESCALER_32, 1250);
```
    - 预分频器 = 32，重装载值 = 1250。
    - IWDG 时钟源为内部 40kHz LSI（低频内部振荡器）。
    - 超时时间计算：
        - 预分频后时钟 = 40kHz / 32 = 1.25kHz
        - 计数器时钟周期 = 1 / 1.25kHz = 0.8ms
        - 超时 = (重装载值 + 1) × 0.8ms = 1251 × 0.8ms ≈ **1s**。
5. **启动后立即喂狗**
```c
iwdg_feed(); // 避免启动就超时
```
6. **主循环中延时 1010ms 后再喂狗**
```c
while (1)
{
    delay_ms(1010);  // 故意超过 1s 喂狗间隔
    iwdg_feed();
    printf("已经喂狗\\r\\n");
}
```
    - 喂狗间隔 1010ms > 1s，明显超出 IWDG 的饲料供应窗口，所以**第一次喂狗还未执行，IWDG 就会产生系统复位**。
7. **现象观察**
    - 串口助手反复打印“请及时喂狗” → 系统不断复位。
    - 若改为 `delay_ms(900)` 喂狗，则程序正常运行，串口持续打印“已经喂狗”。
8. **IWDG 特性**
    - 一旦使能，只能由系统复位关闭，**软件无法停止**。
    - 独立于系统时钟，即使主时钟停振也能工作，安全级别最高。

---

### 四、IWDG 实验结论

- IWDG 是 **自由运行的递减计数器**，减到 0 就会产生复位。
- 超时时间由预分频器和重装载值决定，公式：
**Tout = (4 × 2^prer) × (rlr + 1) / 40kHz**（prer 为 HAL 预分频宏对应值，如 `IWDG_PRESCALER_32` 对应预分频数 32）。
- 软件必须在计数减到 0 之前写入重装键（喂狗），否则系统复位。
- 本实验中故意喂狗间隔超过 1s，因此导致不断复位，验证了 IWDG 的可靠性。

## 第二部分：窗口看门狗 WWDG 实验

### 一、实验目的

9. 掌握 WWDG 的初始化、窗口概念与喂狗时机。
10. 理解**提前唤醒中断 (EWI)** 的作用——在计数器减到 0x40 前触发中断，做最后的补救。
11. 学会检测复位源（判断是 WWDG 复位还是外部复位）。
12. 体会 WWDG 要求**不能太早也不能太晚**喂狗的窗口限制。

### 二、实验硬件

- STM32F103ZET6 开发板
- 串口打印复位信息
- LED 闪烁指示喂狗操作

### 三、实验步骤

13. **复位源检测**
```c
if(__HAL_RCC_GET_FLAG(RCC_FLAG_WWDGRST) != RESET)
{
    printf("看门狗已复位\\r\\n");
    __HAL_RCC_CLEAR_RESET_FLAGS();
}
else printf("外部复位\\r\\n");
```
上电后检查 RCC 的复位标志，判断上次是 WWDG 复位还是外部复位，便于调试。
14. **配置 WWDG**
```c
wwdg_init(0x7F, 0x5F, WWDG_PRESCALER_8);
```
    - 计数器初值 (Counter) = 0x7F（127，最大值）。
    - 窗口值 (Window) = 0x5F（95）。
    - 预分频器 (Prescaler) = 8（对应分频数 8，见寄存器说明）。
    - 使能 EWI（提前唤醒中断）。
    - WWDG 时钟源为 **PCLK1**（APB1 时钟，36MHz），经过可编程预分频器后作为计数器时钟。
15. **超时时间与窗口计算**
    - 设 PCLK1 = 36MHz，预分频数 = 8 → 计数器时钟 = 36MHz / 4096 / 8 ≈ **1098.6 Hz**（因为 WWDG 内部固定 4096 分频，再叠加上可编程预分频器）。
实际上：
T_wwdg = (4096 × 2^WDGTB) / PCLK1，其中 WDGTB 是预分频系数位。
匹配 HAL 库 `WWDG_PRESCALER_8` 对应 WDGTB = 3，则时间周期 = (4096 × 8) / 36MHz ≈ 910.2 µs。
    - 计数器从 0x7F (127) 减到 0x3F (63) 可喂狗窗口下限（当 T6 位由 1 变 0，即计数器从 0x40 跳变到 0x3F 时会产生复位），故最大喂狗周期 ≈ (127 - 63) × 910.2 µs ≈ 58.4 ms。
    - 窗口上限由 W[6:0] = 0x5F (95) 决定，即计数器必须小于等于 95 才能喂狗，太早（>95）也会复位。所以有效喂狗窗口 = 95 - 63 = 32，对应时间约 29 ms。
16. **提前唤醒中断处理 (EWI)**
```c
void HAL_WWDG_EarlyWakeupCallback(WWDG_HandleTypeDef *huart)
{
    HAL_WWDG_Refresh(&g_wwdg_handle); // 在中断里喂狗
    LED1_TOGGLE();
}
```
    - 当计数器减到 **0x40** 时，如果 EWI 使能，就会产生提前唤醒中断（并非复位）。这是最后一次喂狗的机会，如果不喂则再减一个计数到 0x3F 时就会复位。
    - 本例在主循环中根本未喂狗，完全依靠 EWI 中断喂狗，因此只要中断响应及时，系统不会复位。
17. **主循环延时 90ms 并翻转 LED0**
```c
while(1)
{
    delay_ms(90);
    LED0_TOGGLE();
}
```
    - 90ms 大于 WWDG 的最大超时时间（58.4ms），但因为有 EWI 中断喂狗，系统实际不会复位。
    - 如果关闭 EWI 或中断处理不及时，系统将周期性复位。

---

### 四、WWDG 实验结论

- WWDG 是一个 **带窗口机制的递减计数器**，要求喂狗时机必须在 `(Counter <= Window) && (Counter > 0x3F)` 的范围内，否则会产生复位。
- 提前唤醒中断 (EWI) 提供了最后一次喂狗机会（在 0x40 时刻），可以用于记录重要信息或尝试恢复。
- WWDG 时钟来自 PCLK1（APB1），受系统时钟影响，不独立于主时钟。
- 通过复位源标志可识别是 WWDG 复位还是其他复位。
- 本例中虽然主循环延时 90ms 远大于 WWDG 的窗口时间，但由于 EWI 中断每轮回自动喂狗，程序稳定运行，说明正确利用 EWI 可以大大提高系统健壮性。

## 第三部分：IWDG 与 WWDG 的对比总结

### 🔴 相同点

18. **作用相同**：都是用于检测程序异常运行，并在必要时复位微控制器，防止系统卡死。
19. **本质都是递减计数器**：当计数器减到特定值（IWDG 减到 0，WWDG 减到 0x3F）时产生复位。
20. **都需要定期“喂狗”（重装计数器）** 来避免复位。
21. **都能通过标志位判断是否发生了看门狗复位**（IWDG 复位标志在 RCC_CSR 中，WWDG 类似，HAL 库均封装了检测函数）。
22. **都可通过软件使能（代码配置），硬件控制**。
23. **都可以配置预分频器，调整超时时间范围**。

### 🟡 不同点（重点）

| 对比维度         | IWDG（独立看门狗）                                    | WWDG（窗口看门狗）                                                                   |
| ------------ | ---------------------------------------------- | ----------------------------------------------------------------------------- |
| **时钟源**      | 内部低速振荡器 **LSI**（约 40kHz），独立于系统时钟，即使系统时钟故障也能工作。 | **PCLK1**（APB1 总线时钟，最高 36MHz），依赖系统时钟，如果系统时钟失效可能无法工作。                          |
| **计数器位数**    | 12 位递减计数器，重装值最大 0xFFF（4095）。                   | 7 位递减计数器（T[6:0]），仅 bit6 ~ bit0 参与计数，最大 0x7F（127）。                             |
| **复位条件**     | 计数器减到 0 即复位。                                   | 计数器减到 0x3F（T6 位由 1 变 0）时复位。                                                   |
| **喂狗时机限制**   | **无窗口限制**，只要在计数器减到 0 之前喂狗即可。                   | **有窗口限制**，必须在 `(0x3F < Counter <= Window)` 范围内喂狗，太早或太晚都会复位。这可以防止程序异常但仍在喂狗的情况。 |
| **提前警告中断**   | 无。                                             | 有 **EWI 提前唤醒中断**，计数器减到 0x40 时产生中断，可做最后应急处理。                                   |
| **软件是否能关闭**  | 一旦使能，只有复位才能关闭，无法软件停止。                          | 可以通过 DBG 暂停定时器的特性停止（调试时用），且系统复位后自动关闭。                                         |
| **超时时间范围**   | 更广，从几毫秒到几秒甚至更长，由 12 位计数器 + 预分频器决定。             | 相对较短，最多几十毫秒（取决于 PCLK1 和预分频），通常用于需要快速响应的系统。                                    |
| **适用场景**     | 片外干扰、主时钟停振等严重异常保护，要求独立可靠的复位源。                  | 检测程序逻辑错误（如某个任务执行时间过长或过早），要求精确时间窗口的应用。                                         |
| **复位标志检测方式** | `__HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST)`         | `__HAL_RCC_GET_FLAG(RCC_FLAG_WWDGRST)`                                        |

---

### 🔴 IWDG 实验要点、难点、重点

- **重点**：
    - IWDG 的时钟独立，LSI 精度较低（约 40kHz），超时时间计算不能过于精细，需留余量。
    - `HAL_IWDG_Init` 函数内部会写启动使能位，一旦初始化看门狗就立即启动，之后无法关闭。
- **难点**：
    - 上位机调试时，若 IWDG 开启且不及时喂狗，会不断复位导致无法下载程序。建议调试阶段使用 `HAL_DBGMCU_EnableDBGStopMode` 等方式暂停 IWDG。
    - 预分频器与重装值的换算必须准确，否则目标超时时间计算错误。
- **要点**：
    - 喂狗间隔必须**严格小于**超时时间，并考虑程序执行时间波动，建议留 30% 以上余量。
    - 不要在中断服务函数中长时间滞留，以免影响喂狗时机。

### 🟡 WWDG 实验要点、难点、重点

- **重点**：
    - **窗口概念**：必须等到计数器减到窗口值以下才能喂狗，这是 WWDG 与其他看门狗最大的区别。
    - **EWI 中断**：在 0x40 触发，如果使能此中断，必须在中断中清除标志或喂狗，否则下一个计数即复位。
- **难点**：
    - 窗口值与计数器初值的配置需要同时满足时序要求，容易出现太早或太晚喂狗导致复位。
    - WWDG 的时钟源是 PCLK1，在系统进入低功耗或时钟配置改变时会影响超时时间。
- **要点**：
    - `HAL_WWDG_Refresh` 必须在正确的时间窗口内调用，否则复位。
    - 若启用 EWI，中断里喂狗的前提是确保中断不被阻塞，否则仍会复位。
    - 复位源检测可以区分当前复位原因，有利于产品级的日志记录和故障分析。

---

## 六、总结延伸

在可靠系统中，常常会同时启用 IWDG 和 WWDG，前者保证在严重失效时复位，后者精确监控程序时序。根据实际需求灵活配置两个看门狗，是嵌入式工程师必备的技能。
