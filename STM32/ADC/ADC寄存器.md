## 1. ADC 状态寄存器 (ADC_SR)

地址偏移：0x00
复位值：0x0000 0000

这个寄存器记录了 ADC 当前的各种状态，大家可以通过查询这些位来判断转换是否完成、有没有被触发等。

| 位 | 名称 | 说明（老师解读） |
| --- | --- | --- |
| 0 | **AWD** | 模拟看门狗标志位。当 ADC 转换结果超出了高低阈值（见后面的 ADC_HTR/LTR），硬件自动置 1。如果使能了中断，会触发中断。读 ADC_SR 再写 0 可以清除。 |
| 1 | **EOC** | 规则通道转换结束标志。当一组规则通道（或单个）转换完成，该位硬件置 1。如果 DMA 模式使能，该位也会在 DMA 传输触发后置 1。读取 ADC_DR（规则数据寄存器）可清除此位，或直接写 0 清除。 |
| 2 | **JEOC** | 注入通道转换结束标志。注入组转换完成后置 1，读取 ADC_JDRx 后自动清除，也可以写 0 清。 |
| 3 | **JSTRT** | 注入通道转换开始标志。当注入转换被触发（比如外部触发或软件触发）时硬件置 1，读取后自动清除。 |
| 4 | **STRT** | 规则通道转换开始标志。规则组开始转换时硬件置 1，读取后自动清除。 |

**HAL 库关联：**`HAL_ADC_PollForConversion()` 就会不断查询 `EOC` 位。而 `__HAL_ADC_CLEAR_FLAG()` 这些宏就是直接操作 SR 的位清除。

## 2. ADC 控制寄存器 1 (ADC_CR1)

地址偏移：0x04
复位值：0x0000 0000

这个寄存器负责 ADC 的基本功能配置：看门狗、中断、扫描模式等。

| 位 | 名称 | 说明 |
| --- | --- | --- |
| [4:0] | **AWDCH[4:0]** | 模拟看门狗通道选择。你希望看门狗监视哪个通道？00000 是通道 0，00001 是通道 1，…… 10001 是通道 17。注意 17 是内部参考电压或温度传感器的通道（带的时候会用到）。 |
| 5 | **EOCIE** | 规则转换结束中断使能。置 1 后，当 EOC 标志置位时产生中断。 |
| 6 | **AWDIE** | 模拟看门狗中断使能。看门狗事件产生中断。 |
| 7 | **JEOCIE** | 注入转换结束中断使能。 |
| 8 | **SCAN** | 扫描模式使能。**1**：扫描模式。ADC 会按规则序列里的顺序依次转换所有选中的通道。**0**：非扫描模式，每次只转换 SQR3 指定的第一个通道。 |
| [22:19] | **DUALMOD[3:0]** | 双 ADC 模式选择（ADC1 和 ADC2 同步等）<br>0000：独立模式（各干各的）<br>0001：混合的规则+注入同步模式<br>0010：规则同步+注入同步模式<br>… 等等，一共 9 种模式。这个在需要同时采两路信号同步分析时非常重要。**注意：这个位只在 ADC1 的 CR1 里有效，ADC2/3 的相应位是保留的。** |
| 23 | **JAWDEN** | 注入通道看门狗使能。是否让看门狗在注入转换时也工作。 |
| 24 | **AWDEN** | 规则通道看门狗使能。是否让看门狗在规则转换时工作。 |

**HAL 库关联：**`HAL_ADC_Start_IT()` 会设置 `EOCIE` 位。`HAL_ADCEx_MultiModeStart_DMA()` 会配置 `DUALMOD` 位。

## 3. ADC 控制寄存器 2 (ADC_CR2)

地址偏移：0x08
复位值：0x0000 0000

这个寄存器很关键，控制 ADC 的启动/停止、外部触发、数据对齐、校准等。

| 位 | 名称 | 说明 |
| --- | --- | --- |
| 0 | **ADON** | ADC 开关。**1**：开启 ADC 并开始转换（软件触发时）；**0**：关闭 ADC，省电。注意上电后首次置 1 会唤醒 ADC，需要稳定时间，再置 1 才真正开始转换。 |
| 1 | **CONT** | 连续转换模式。**1**：连续转换，一轮规则组完成后自动开始下一轮。**0**：单次转换，完成后停止。 |
| 2 | **CAL** | 开始校准。软件置 1 启动校准，校准完成后硬件自动清 0。校准必须在 ADC 上电之后、开始转换之前进行。 |
| 3 | **RSTCAL** | 复位校准。软件置 1 将校准寄存器重置，硬件完成后清 0。如果测量值漂移了，可以重新校准。 |
| 4 | 保留 | 无 |
| [7:6] | **EXTTRIG** | 规则组外部触发使能。**1**：使用外部触发信号启动规则组转换。触发源由 EXTSEL[2:0] 选择。 |
| [10:8] | **EXTSEL[2:0]** | 规则组外部触发事件选择。<br>000：定时器1 的 CC1 事件<br>001：定时器1 的 CC2 事件<br>010：定时器1 的 CC3 事件<br>011：定时器2 的 CC2 事件<br>100：定时器3 的 TRGO 事件<br>101：定时器4 的 CC4 事件<br>110：外部中断线 11（比如 GPIO 的引脚触发）<br>111：SWSTART（软件触发，就是 `ADON` 位触发） |
| 11 | **ALIGN** | 数据对齐。**0**：右对齐（低12位有效）<br>**1**：左对齐（高12位有效，低4位为0） |
| [14:12] | **JEXTTRIG** | 注入组外部触发使能。**1**：使用外部触发启动注入组转换。 |
| [17:15] | **JEXTSEL[2:0]** | 注入组外部触发事件选择。编码同 EXTSEL，但事件源列表不同，可以查询手册。 |
| 19 | 保留 |   |
| 20 | 保留 |   |
| 21 | **SWSTART** | 规则组软件开始转换。在 `EXTTRIG=0` 时，置 1 会立即开始规则通道转换（单次或连续）。注意 `ADON` 也用。实际上通常用 `SWSTART` 启动。 |
| 22 | **JSWSTART** | 注入组软件开始转换。类似上面。 |
| [24:23] | **TSVREFE** | 温度传感器和 VREFINT 使能。**1**：启用内部温度传感器（通道16）和内部参考电压（通道17）。注意这两个通道只能在上电后需要时打开，否则可能干扰测量。 |

**HAL 库关联：**`HAL_ADC_Start()` 会依次设置 `ADON`、等待稳定，然后置 `SWSTART`。`HAL_ADCEx_Calibration_Start()` 会操作 `RSTCAL` 和 `CAL`。

## 4. ADC 采样时间寄存器 1 & 2 (ADC_SMPR1, ADC_SMPR2)

地址偏移：0x0C, 0x10

这两个寄存器一起为 18 个外部通道（0~17）分别设置采样时间。采样时间越长，精度越高，但转换时间也越长。

- ADC_SMPR1 管理通道 10~17 的采样时间设置。
- ADC_SMPR2 管理通道 0~9 的采样时间设置。

每个通道占用 3 位：

| SMPx[2:0] | 采样周期数（以 ADCCLK 为单位） |
| --- | --- |
| 000 | 1.5 周期 |
| 001 | 7.5 周期 |
| 010 | 13.5 周期 |
| 011 | 28.5 周期 |
| 100 | 41.5 周期 |
| 101 | 55.5 周期 |
| 110 | 71.5 周期 |
| 111 | 239.5 周期 |

例如，在 SMPR2 中，低 3 位（bit 0~2）是通道 0 的 SMP，bit 3~5 是通道 1 的 SMP……

**HAL 库关联：**`HAL_ADC_ConfigChannel()` 内部根据你设置的采样时间参数，填入对应的 SMPR1 或 SMPR2 的相应位段。

## 5. ADC 注入通道数据偏移寄存器 1～4 (ADC_JOFR1～4)

地址偏移：0x14, 0x18, 0x1C, 0x20

注入组有 4 个通道位置，各自有一个偏移寄存器，用于在转换结果上加上一个带符号的偏移量（会直接修改 JDRx 里的值，常用于传感器线性修正之类的）。

- 每个寄存器 32 位，但只有低 12 位有效（因为 ADC 是 12 位）。数值可以正可以负，以二进制补码形式存储：0x000 ~ 0xFFF，如果最高位是 1，就是负数。例如 0xFFF 表示 -1。实际作用：`JDRx_实际 = ADC_转换结果 + JOFRx`。

## 6. ADC 看门狗阈值寄存器 (ADC_HTR, ADC_LTR)

地址偏移：0x24, 0x28

- **ADC_HTR**：高阈值（12位有效），若转换结果大于此值，且看门狗使能，则产生 AWD 事件。
- **ADC_LTR**：低阈值（12位有效），若转换结果小于此值，且看门狗使能，则产生 AWD 事件。

阈值也受到数据对齐影响：如果是左对齐，那么值的高 12 位是这个阈值比较的对象；右对齐就是低 12 位。

**HAL 库关联：**`HAL_ADC_AnalogWDGConfig()` 就是写这三个寄存器（AWDCH、HTR、LTR）相关位。

---

## 7. ADC 规则序列寄存器 1～3 (ADC_SQR1, ADC_SQR2, ADC_SQR3)

地址偏移：0x2C, 0x30, 0x34

这三个寄存器共同决定规则通道的转换顺序和个数。你可以最多设置 16 个规则转换（一个序列）。每个通道用 5 位二进制编码（0～17）填充。

- **SQR1** 的 bit [23:20] 是 **L[3:0]**：规则序列的长度（1～16）。写 L = N-1 表示有 N 个转换。例如 L=0 表示只有1个转换。
- 剩下的位（SQR1[19:0]、SQR2[31:0]、SQR3[31:0]）依次存放规则序列中的第 1、第 2…… 第 16 个转换通道，每个占 5 位。
    - 在 SQR3 中，低 5 位（bit 4:0）是序列的 **第 1 个转换** 的通道；bit 9:5 是第 2 个转换…… 以此类推。当 L<6 时，后面未使用的位无效。
    - SQR2 存序列中第 7～12 个转换。
    - SQR1 存序列中第 13～16 个转换。

**HAL 库关联：**`HAL_ADC_ConfigChannel()` 会根据你设定的通道排名（Rank）和总通道数（NbrOfConversion）自动计算并填入 SQR 寄存器。

## 8. ADC 注入序列寄存器 (ADC_JSQR)

地址偏移：0x38

注入组最多 4 个转换，设置方式类似规则组。

- bit [21:20] 是 **JL[1:0]**：注入序列长度（1～4），编码为 N-1。
- 剩下的位：JSQR 的低 5 位（bit 4:0）是第一个注入转换的通道，bit 9:5 是第二个，bit 14:10 是第三个，bit 19:15 是第四个。不用的部分忽略。

注入通道触发后，会按顺序依次转换，结果存入对应的 JDRx 寄存器。注入通道可以打断规则通道（相当于“中断”规则的转换），保证重要的信号及时采集。

**HAL 库关联：**`HAL_ADCEx_InjectedConfigChannel()` 会填充 JSQR。

---

## 9. ADC 规则数据寄存器 (ADC_DR)

地址偏移：0x4C

存放最近一次规则组转换的结果。它是一个 32 位寄存器，但有效位和格式取决于 ALIGN 位：

- 右对齐：`DR[11:0]` 是结果，其他位为 0。
- 左对齐：`DR[15:4]` 是结果，`DR[3:0]` 始终为 0，高 16 位也可能为 0 或符号扩展（取决于具体芯片，通常是 0）。

当你读这个寄存器时，**硬件会自动清除 EOC 标志**（除非 ADC_SR 没有通过读清除？实际上读 DR 会清除 EOC）。如果开了 DMA，每次转换完成后数据自动移动到内存，无需软件干预。

---

## 10. ADC 注入数据寄存器 1～4 (ADC_JDR1～4)

地址偏移：0x3C (JDR1), 0x40 (JDR2), 0x44 (JDR3), 0x48 (JDR4)

每个 32 位，只低 16 位有意义，存放对应注入通道的转换结果。读取时自动清除 JEOC 标志。如果 JEOC 产生中断，读取对应 JDRx 即可获取最新数据（也可以配合偏移寄存器做修正）。

## 11. ADC 通用控制寄存器 (ADC_CCR)

地址：这个不属于单个 ADC 的寄存器，而是多个 ADC 共享的控制寄存器，基地址在 APB2 总线（0x40012300 范围附近，对于 STM32F103 是 0x40012308）。为了完整性，我们也要讲一下，因为有时候配置 ADC 时钟分频、温度传感器时会用到。

ADC_CCR 的位：

| 位 | 名称 | 说明 |
| --- | --- | --- |
| [17:0] | 保留 |   |
| 18 | **TSVREFE** | 温度传感器和 VREFINT 使能。注意在单个 ADC 的 CR2 里也有这一位，但在 F103 上，它实际上是在 ADC_CCR 中所有 ADC 共用的。配置任何一个 ADC 的 CR2 的这个位都会反映到这个寄存器。所以通常直接操作 ADC_CCR 来统一控制。 |
| [21:19] | 保留 |   |
| [24:22] | 保留 |   |
| [26:25] | 保留 |   |
| [29:27] | 保留 |   |
| [31:30] | 保留 |   |

实际上，ADC_CCR 最重要的位就是 `TSVREFE`（18 位），其他大部分是保留的（在 F4 系列有更多选项）。在 HAL 库中，`__HAL_RCC_ADC1_CLK_ENABLE()` 使能时钟后，如果需要温度传感器，会调用 `HAL_ADC_EnableVrefintTempSensor()` 等宏来设置。

但是注意，在 STM32F103 的手册中，ADC_CR2 的 TSVREFE 位和 ADC_CCR 的 TSVREFE 是同一个控制效果，实际上是通过 ADC_CCR 来映射的。所以通常在 HAL 中会直接操作 ADC_CCR。

## 寄存器速览表 （方便你记忆）

| 寄存器 | 主要功能 |
| --- | --- |
| ADC_SR | 看状态标志：AWD, EOC, JEOC, STRT, JSTRT |
| ADC_CR1 | 看门狗通道选择、中断使能、双模、扫描模式 |
| ADC_CR2 | 开关、连续、触发源、对齐、软件开始、校准、温度传感器使能 |
| ADC_SMPR1/2 | 各通道采样时间配置 |
| ADC_JOFR1～4 | 注入通道偏移量 |
| ADC_HTR/LTR | 看门狗阈值 |
| ADC_SQR1～3 | 规则序列顺序和长度 |
| ADC_JSQR | 注入序列顺序和长度 |
| ADC_DR | 规则转换结果 |
| ADC_JDR1～4 | 注入转换结果 |
| ADC_CCR | 共用控制：温度传感器、时钟分频（F1 中主要为 TSVREFE） |

## HAL 库是怎样用这些寄存器的？

- **初始化**（`HAL_ADC_Init`）：主要配置 `ADC_CR1` 的 SCAN、DUALMOD 等；配置 `ADC_CR2` 的基本模式。
- **配置通道**（`HAL_ADC_ConfigChannel`）：填充 `SMPR` 的采样时间，并按 Rank 填写 `SQR` 或 `JSQR`。还可以使能看门狗并设 AWDCH。
- **开启 ADC**（`HAL_ADC_Start`）：先置 `ADON`，等待稳定，如果无外部触发则置 `SWSTART`。
- **查询转换**（`HAL_ADC_PollForConversion`）：循环读 `SR` 的 `EOC` 位。
- **中断模式**：使能 `CR1` 的 `EOCIE`，在中断服务函数里读 `DR`。
- **DMA 模式**：使能 `ADC_CR2` 的 DMA 位（手册里实际是 `CR2` 的 bit 8 DMA 功能使能？F103 的 `CR2` 有专门的 `DMA` 位，之前我省略了）。查手册：CR2 的 bit 8 是 **DMA** 位，置 1 时每次规则组转换结束触发一次 DMA 请求。

补充一个经常被问到的位：

- `ADC_CR2` 的 bit 8：**DMA** 的位置，使能 DMA 模式，使能后每次 EOC 事件产生 DMA 请求，自动将 `DR` 值搬运到内存。
