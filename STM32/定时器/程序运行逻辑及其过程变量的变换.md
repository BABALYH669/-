下面我按“程序运行流程 → 按键触发高电平后两变量如何变化”的思路，把 **main.c** 和 **gtim.c** 里和这两个变量相关的关键路径串起来讲清楚。重点会解释：

```c
uint8_t  g_timxchy_cap_sta = 0;
uint16_t g_timxchy_cap_val = 0;
```

---

## 1）先看整体运行过程（从 main 到捕获中断）

### main.c 主要做了这些事

1. `HAL_Init()`：初始化 HAL
2. `sys_stm32_clock_init(RCC_PLL_MUL9)`：设置时钟
3. `delay_init(72)`、`usart_init(115200)`、`led_init()`
4. **初始化输入捕获定时器**：
```c
gtim_timx_cap_chy_init(0xFFFF,72-1);
```
5. 进入 while(1) 循环，不断检测：
```c
if(g_timxchy_cap_sta & 0x80)
{
    temp = g_timxchy_cap_sta & 0x3F;
    temp *= 65536;
    temp += g_timxchy_cap_val;
    printf("HIGH:%d  us\\r\\n",temp);
    g_timxchy_cap_sta = 0;
}
```

> 结论：
`main` 负责“等待捕获结果完成”（看 `g_timxchy_cap_sta` 的 0x80 位），一旦完成就把两个变量组合成 us 打印，然后把 `g_timxchy_cap_sta` 清零，等待下一次测量。

## 2）定时器捕获初始化后，系统处于什么状态？

在 `gtim_timx_cap_chy_init(arr, psc)`：

- `g_timx_cap_chy_handle.Instance = TIM5;`
- `Prescaler = psc = 72-1`
- `Period = arr = 0xFFFF`

然后配置输入捕获通道1（PA0）：

```c
timx_ic_cap_chy.ICPolarity = TIM_ICPOLARITY_RISING;   // 初始检测上升沿
HAL_TIM_IC_ConfigChannel(... TIM_CHANNEL_1)
```

还打开了两个中断相关机制（非常关键）：

6. 开了 **输入捕获中断**（`HAL_TIM_IC_Start_IT`）
7. 开了 **更新中断**（计数溢出时触发）：
```c
__HAL_TIM_ENABLE_IT(&g_timx_cap_chy_handle,TIM_IT_UPDATE);
```

GPIO 配置为 PA0 外部输入（AF_PP、下拉）。

---

## 3）两个变量在整个测量过程的“角色”是什么？

### `g_timxchy_cap_sta`（状态/计数位）

它是一个位域（你代码里用到了 0x80、0x40、0x3F）：

- **0x40 位**：已经检测到“上升沿”（开始计时）
- **0x80 位**：本次测量已经完成（检测到结束条件后置位）
- **低 6 位（0x3F）**：用于累计“溢出次数”（每次溢出就 +1）

因此它既是状态机，也是定时溢出计数器。

### `g_timxchy_cap_val`

- 用来保存**结束沿那一刻 TIM5 捕获寄存器的值**（16位）
- 最终 `main` 里用：
\[
总时间(\mu s)= (溢出次数\times 65536) + 捕获值
\]
因为 TIM5 计数范围是 0~0xFFFF（65536 个计数周期一轮）。

## 4）关键流程：按下按键并进入“高电平测量”后，两变量怎么变化？

假设：按键输入最终会让 PA0 从 **低电平 → 高电平**（并持续一段时间），然后又回到低电平。

定时器配置逻辑是：

- **初始捕获极性为上升沿**（RISING）
- 捕获到上升沿后会把极性切换为**下降沿**（FALLING）
- 捕获到下降沿后会把定时器关掉、把 `g_timxchy_cap_sta` 的完成位等置位

下面按事件分阶段讲。

---

# 阶段 A：初始等待（无按下 / 按下前）

初始时在全局区：

```c
g_timxchy_cap_sta = 0;
g_timxchy_cap_val = 0;
```

此时：

- `main` 的 `if(g_timxchy_cap_sta & 0x80)` 不成立，不打印
- `TIM5` 在运行，等待 **上升沿捕获**（ICPolarity=RISING）

---

# 阶段 B：第一次上升沿到来（按下导致 PA0 从低变高）

触发 **输入捕获中断** → 进入：

```c
HAL_TIM_IC_CaptureCallback()
```

进入后逻辑是：

```c
if((g_timxchy_cap_sta & 0x80) == 0)   // 本次尚未完成
{
    if(g_timxchy_cap_sta & 0x40)     // 是否已经捕获过上升沿？
    { ... }
    else
    {
        g_timxchy_cap_sta = 0;
        g_timxchy_cap_val = 0;
        g_timxchy_cap_sta |= 0x40;   // 标记捕获到了上升沿
        __HAL_TIM_DISABLE(&g_timx_cap_chy_handle);
        __HAL_TIM_SET_COUNTER(&g_timx_cap_chy_handle,0);
        ...
        // 切换为下降沿捕获
        TIM_SET_CAPTUREPOLARITY(... TIM_ICPOLARITY_FALLING);
        __HAL_TIM_ENABLE(&g_timx_cap_chy_handle);
    }
}
```

所以在“上升沿发生”的瞬间，两变量变化为：

### ✅ `g_timxchy_cap_sta`：

- 原来：`0x00`
- 变为：`0x40`
- 也就是二进制：`0100 0000`

### ✅ `g_timxchy_cap_val`：

- 原来：`0`
- 重新清零：仍为 `0`

并且做了两件事：

8. TIM5 计数器清零从头开始计时（`__HAL_TIM_SET_COUNTER(...,0)`）
9. 捕获极性从 **上升沿**切到 **下降沿**
    - 这意味着后面要找“高电平结束”（下降沿）。

> 从这一刻开始，定时器开始“累计高电平持续时间”。

---

# 阶段 C：高电平持续期间发生若干次溢出（Update中断）

如果按键保持高电平时间很长，TIM5 可能从 0 数到 0xFFFF 再溢出。
溢出会触发：

```c
HAL_TIM_PeriodElapsedCallback()
```

里面只有在满足条件时才对状态计数：

```c
if((g_timxchy_cap_sta & 0x80)==0)
{
    if(g_timxchy_cap_sta & 0x40)
    {
        if((g_timxchy_cap_sta & 0x3F) == 0x3F)
        {
            ...
            g_timxchy_cap_sta |= 0x80;
            g_timxchy_cap_val = 0xFFFF;
        }
        else
        {
            g_timxchy_cap_sta++; // 关键：+1
        }
    }
}
```

### 在未达到最大溢出次数前：

每次溢出：

- `g_timxchy_cap_sta++`

因为当前 `g_timxchy_cap_sta` 已经有 0x40 位为1，所以递增会不断填充低6位，用于“溢出次数”。

例如：

- 第1次溢出前：`0x40` （低6位=0）
- 第1次溢出后：`0x41` （低6位=1）
- 第2次溢出后：`0x42`
- ...
- 当低6位到 `0x3F` 时进入“超出量程/结束”的分支。

### 到达最大值分支时：

当 `(g_timxchy_cap_sta & 0x3F) == 0x3F`：

- 把捕获极性设置回默认（RISING）
- 置完成标志：`g_timxchy_cap_sta |= 0x80`
- `g_timxchy_cap_val = 0xFFFF`

这相当于：高电平太长，溢出次数到上限了，直接认为测量结束。

---

# 阶段 D：下降沿到来（高电平结束）

下降沿触发输入捕获中断，进入 `HAL_TIM_IC_CaptureCallback()`。

此时因为已经经历过上升沿，所以：

- `g_timxchy_cap_sta & 0x40` **为真**
- `g_timxchy_cap_sta & 0x80` **为假（尚未结束）**

于是进入第一分支：

```c
g_timxchy_cap_sta |= 0x80;  // 置完成标志
g_timxchy_cap_val = HAL_TIM_ReadCapturedValue(...); // 读取捕获值
TIM_RESET_CAPTUREPOLARITY(...);
TIM_SET_CAPTUREPOLARITY(..., TIM_ICPOLARITY_RISING); // 切回上升沿
```

因此在“下降沿发生”的瞬间：

### ✅ `g_timxchy_cap_sta`：

- 原来：形如 `0x4X`（X=低6位溢出次数）
- 变为：`0xC X`（把 0x80 加上去）
    - 即：`0x80` + `0x40` + 溢出低6位

举例：

- 若溢出低6位=0x05
    - 上升沿后状态：`0x45`
    - 下降沿后完成：`0xC5`

### ✅ `g_timxchy_cap_val`：

- 变为：捕获到的 TIM5 当前计数值（16位）
- 它代表“距离最后一次溢出到下降沿的计数偏移量”。

---

## 5）回到 main.c：怎么把两个变量组合成 HIGH 的持续时间？

下降沿后：

- `g_timxchy_cap_sta` 的 0x80 变为 1
- 所以 `main` 的 `if(g_timxchy_cap_sta & 0x80)` 会成立并执行计算：

```c
temp = g_timxchy_cap_sta & 0x3F;  // 取低6位：溢出次数
temp *= 65536;                     // 每次溢出对应 65536 个计数
temp += g_timxchy_cap_val;        // 加上最后那段未溢出的计数
printf("HIGH:%d  us\\r\\n",temp);
g_timxchy_cap_sta = 0;
```

也就是说：

- **低6位** = Update次数（溢出次数）
- **g_timxchy_cap_val** = 最终下降沿捕获的计数值
- 合成总计数 → 被当作“us”打印出来（你这套换算隐含了定时器时钟与 1us 的对应关系；若你希望我也帮你推导实际1计数对应多少us，我也可以继续算给你）

## 6）总结：两变量“按顺序”的典型变化轨迹

假设高电平不太长（不会达到最大溢出）：

10. 初始：
    - `g_timxchy_cap_sta = 0x00`
    - `g_timxchy_cap_val = 0x0000`
11. 上升沿（开始计时）：
    - `g_timxchy_cap_sta: 0x00 → 0x40`
    - `g_timxchy_cap_val: 0 → 0`
12. 若干次溢出（期间每溢出一次）：
    - `g_timxchy_cap_sta: 0x40 → 0x41 → 0x42 → ...`
    - `g_timxchy_cap_val` 不变（仍保持0直到下降沿捕获）
13. 下降沿（结束计时）：
    - `g_timxchy_cap_sta: 0x4X → 0xC X`
    - `g_timxchy_cap_val: 0x0000 → 捕获值(0~0xFFFF)`
14. main 打印后清零：
    - `g_timxchy_cap_sta: 0xCX → 0x00`
    - `g_timxchy_cap_val` 没有被清（但下一次上升沿会把它重新清为0）
